# Zentrix API

Base path `/v1`. Full schema: [`openapi.json`](openapi.json) (generated by `python -m scripts.export_openapi`;
a test fails if it is stale). Interactive docs at `/docs` when the server runs. **Not financial advice.**

## Auth flow (Google sign-in)

1. The app signs in with `google_sign_in` and gets a Google **ID token**.
2. `POST /v1/auth/google {id_token, device_name?}` -> `{access_token, refresh_token, expires_in, user}`.
   The server verifies the ID token against Google's keys (issuer, audience = our OAuth client IDs, expiry,
   verified email). First sign-in creates the account.
3. Send `Authorization: Bearer <access_token>` (valid 15 min).
4. On `401 token_expired`, call `POST /v1/auth/refresh {refresh_token}` -> new pair. **Each refresh token works
   once.** Re-using an old one is treated as theft: every session from that sign-in is revoked
   (`refresh_token_reused`). The app must serialise refreshes (one in flight; others wait for its result).
5. Store both tokens in secure storage (flutter_secure_storage). Never log them.

| Endpoint | Auth | Purpose |
|---|---|---|
| `POST /v1/auth/google` | none (10/min per IP) | Sign in / sign up |
| `POST /v1/auth/refresh` | none (30/min per IP) | Rotate tokens |
| `POST /v1/auth/logout` | none | Revoke this device's refresh token (idempotent, 204) |
| `POST /v1/auth/logout-all` | bearer | Revoke all sessions incl. outstanding access tokens (204) |
| `GET /v1/me` | bearer | Profile: plan, `premium_access`, locale (`en`/`ur`), timezone |
| `PATCH /v1/me` | bearer | Update `display_name`, `locale`, `timezone` (IANA) |
| `DELETE /v1/me` | bearer | **Delete account and all data** (Play requirement). Irreversible, 204 |

`premium_access` is `true` for everyone while `PREMIUM_ENFORCED=false` (billing is not built).

## Market reference data (public, 120/min per IP)

| Endpoint | Purpose |
|---|---|
| `GET /v1/instruments` | Instruments across asset classes. Filters: `asset_class` (fx, metal, commodity, crypto), `instrument_type` (spot, perpetual, future, cfd), `venue`, `q`, `include_inactive`, `limit` (<= 200), `offset` |
| `GET /v1/timeframes` | `1m` ... `1w` with seconds |
| `GET /v1/venues` | Exchanges and data vendors |

Each instrument lists its venue feeds (`listings`) with a status: `active`, `planned`, `restricted` (for example
silver on the free Twelve Data plan) or `disabled`. `active=false` instruments have no usable feed yet.

## Ops

`GET /health` (liveness), `GET /ready` (database + Redis; 503 when not ready). Every response has `X-Request-ID`.

## Errors

Always `{"error": {"code": "...", "message": "...", "details": ...}}`. Codes: `unauthorized`, `invalid_token`,
`token_expired`, `token_revoked`, `invalid_google_token`, `google_token_expired`, `email_not_verified`,
`invalid_refresh_token`, `refresh_token_expired`, `refresh_token_reused`, `rate_limited` (429 + `Retry-After`),
`validation_error` (422), `not_found`, `auth_not_configured` / `google_keys_unavailable` (503).
